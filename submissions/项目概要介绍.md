## 一、背景与痛点

高校课程内容散落在教材、课件、教案等非结构化文档中，知识点缺乏显式关联：学生难以建立课程整体结构、学习容易"迷路"；教师手工构建知识图谱工作量大、周期长，难以推广。与此同时，大语言模型已具备从自然语言文档中抽取实体与语义关系的能力——用 AIGC 把"数周级手工建图"压缩为"上传即得"，再用基于图谱的问答与路径推荐为学生提供个性化导航，正是本赛题要解决的问题。

## 二、方案总览

本系统是一套覆盖 **"资料上传 → 文档解析 → 知识抽取与关系构建 → 图谱生成与可视化 → 智能学习导航"** 完整链路的 Web 应用（Next.js 15 + TypeScript 全栈）：

- **教师端**：上传 PDF/TXT 课程资料，系统自动解析（含 GBK 编码自动回退）、按章节切块、调用大模型分批抽取知识点与前置/包含/相关三类关系（zod schema 强约束 + 三重清洗保证图数据合法），一键生成可交互的知识图谱；支持教师**手动增删改节点与关系**（赛题加分项）实时预览。
- **学生端**：浏览 ECharts 力导向图谱（缩放/拖拽/点击查看详情），按章节勾选"已掌握"，系统基于前置关系图遍历推荐下一步学习内容（解锁价值/难度/章节三重排序，附推荐理由）；智能问答基于自研轻量 RAG——bigram 词频检索教材片段，大模型流式生成**严格依据教材、带参考章节引用、教材未涉及即拒答**的回答。
- **工程亮点**：图存储抽象为 GraphStore 接口，Neo4j 与 JSON 文件双引擎自动探测降级；未配置大模型 Key 时自动进入离线演示模式（内置《数据结构》37 知识点/51 关系演示数据集），**评审零配置即可跑通全流程**。

## 四、技术栈与创新点

**技术栈**：Next.js 15（App Router）· React 19 · TypeScript · Vercel AI SDK 5（generateObject 结构化抽取 / streamText 流式问答）· DeepSeek/通义千问（OpenAI 兼容接入）· Neo4j 5（可选）· ECharts 5 · Tailwind CSS · Vitest + Playwright。

**创新点**：
1. **双引擎图存储自动降级**——Neo4j 连通性探测失败自动切 JSON 文件存储，业务层零感知，兼顾生产规格与零配置评审；
2. **零依赖中文 RAG**——bigram+单字低权重的词频检索替代向量库，中文召回经测试集验证，行为确定可单测；
3. **引用先行的流式问答**——参考章节与引用片段先于正文到达前端，可溯源、抗幻觉；
4. **离线演示模式作为一等公民**——无 Key 全功能可演示，`demoMode` 标志保证演示数据与真实抽取永不混淆；
5. **诚实性工程**——所有未实测指标在代码（`timing`/`demoMode` 字段）与材料（合规对照表"未实测项清单"）双层面显式披露。

- TypeScript 类型检查 ✓；Vitest 单元测试 **18/18** ✓（解析/检索/推荐算法全覆盖）；
