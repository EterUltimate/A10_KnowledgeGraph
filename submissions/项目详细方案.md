## 一、项目概述

### 1.1 项目背景

高校课程内容长期以教材、PPT、教案等非结构化文档形式存在，知识点分散、缺乏显式的关联关系。学生难以快速建立课程整体结构认知，学习过程中容易"迷路"；教师则苦于知识图谱构建高度依赖手工整理——工作量大、周期长、难以规模化推广，这限制了知识图谱这一在可视化学习上极具价值的技术在高校教学中的落地。

与此同时，以大语言模型（LLM）为代表的 AIGC 技术为该问题提供了新的解法：LLM 具备从自然语言文档中自动抽取实体（知识点）与语义关系（前置、包含、相关）的能力，可将图谱构建从"专家数周级手工工作"压缩为"上传文档后的一分钟级自动流程"；再辅以基于图谱的检索增强问答（RAG）与图遍历式学习路径推荐，即可为每位学生提供"千人千面"的学习导航体验，推动教学从"经验驱动"走向"数据驱动"。

本团队按照赛题要求，完整实现了一套 **"课程资料上传 → 文档解析 → 知识点抽取与关系构建 → 知识图谱生成与可视化 → 智能学习导航（个性化路径推荐 + RAG 知识问答）"** 全链路 Web 系统，并围绕"零配置可评审、可测试、可交接"做了大量工程化设计。

### 1.2 项目目标

1. **对教师**：上传课程资料（PDF/TXT），系统自动解析、抽取知识点与关系、生成可交互的知识图谱，并支持教师手动增删改节点与关系（赛题明确鼓励的加分项），把图谱构建门槛降到"会上传文件即可"。
2. **对学生**：浏览图谱、点击节点查看知识点详情、勾选"已掌握"、获得基于前置关系的个性化学习路径推荐；随时向智能助手提问，获得**基于教材内容、带章节引用、可溯源**的回答，教材未涉及的问题会被明确拒答而非编造。
3. **对评审/部署方**：无需安装 Neo4j、无需申请大模型 Key，`npm install` + `npm run build` 即可离线跑通全部功能进行评审；配置 Key 与 Neo4j 后可无缝切换在线模式与生产图数据库。

### 1.3 赛题四大问题的对应思路

| 赛题提出的问题 | 本系统的解法（详见第四节） |
| --- | --- |
| （1）非结构化文档的知识抽取 | PDF/TXT 解析（含 GBK 自动回退）→ 章节感知切块 → LLM 分批并行结构化抽取（zod schema 强约束）→ 三重关系清洗；无 Key 时返回人工预标注的内置《数据结构》演示数据集保证全流程可跑 |
| （2）图谱的可视化与交互 | ECharts Graph 力导向图：缩放/拖拽（`roam`）、三类关系分色 + 中文边标签、节点大小映射难度、节点点击联动详情卡片 |
| （3）个性化学习路径生成 | 掌握勾选持久化 → 基于 PREREQUISITE 关系的图遍历（O(V+E)）→ "解锁价值 / 难度 / 章节"三重排序，附推荐理由 |
| （4）知识问答与检索增强 | 自研轻量 RAG：bigram+单字词频检索 → `streamText` 流式生成 → **引用数据部件先于正文返回**；提示词强约束"只依据教材回答、未涉及则拒答" |

## 二、需求分析

### 2.1 用户与角色

系统面向两类用户，通过 NextAuth v5 实现登录态与角色区分（`src/auth.ts`、`src/lib/auth-roles.ts`、`src/middleware.ts`）：

- **教师（teacher）**：使用上传页与图谱管理页。核心诉求：资料上传、生成进度/结果查看、图谱预览与手动修正。
- **学生（student）**：使用学生端三页（图谱/问答/路径）。核心诉求：浏览学习、提问、标记掌握、获得推荐。

权限判定采用与运行时解耦的纯函数 `decideTeacherAccess`：未登录返回 `unauthorized`（401），角色不足返回 `forbidden`（403），教师角色放行。该设计使权限逻辑可独立单元测试。

### 3.3 核心数据流

**上传建图链路**（`POST /api/course/upload`，同步处理，返回耗时分解）：

1. 前端 `UploadPanel` 选定课程 ID/名称与 PDF/TXT 文件提交，进入"正在解析并生成知识图谱…"状态；
2. 路由校验文件类型与大小（≤20MB），注册/更新课程（`course.service` → `courses.json`）；
3. `parseFile`：PDF 走 pdf-parse 抽取文本，TXT 按 UTF-8 解码并检测替换符 U+FFFD 自动回退 GBK；
4. `cleanText` 清洗（去页码/页眉/控制字符/多余空行）→ `chunkText` 章节感知切块（默认 800 字，抽取用 1600 字）；
5. `extractKnowledge`：离线模式直接返回内置演示数据集；在线模式按块并行调用 LLM（并发 3、块数上限 6），zod schema 强约束输出，名称归一化去重合并；
6. `extractRelations`：同类抽取关系，经"类型白名单 → 端点存在性 → 自环/重复"三重清洗；
7. `GraphStore.buildGraph` 单事务批量写入知识点与关系；`saveChunks` 按 courseId 覆盖写入 RAG 语料（重传同课程整体替换，防语料膨胀）；
8. 返回 `UploadResult`：知识点/关系/文本块数量、`timing`（解析/抽取/合计毫秒）、`demoMode` 标志；前端展示结果并提供"查看知识图谱 / 修正图谱"跳转。

**RAG 问答链路**（`POST /api/qa`，流式）：

1. `ChatPanel`（useChat）发送问题；
2. `rag.service.retrieve`：问句分词（中文 bigram + 英文单词 + 单字辅助集）→ 对课程语料逐块打分（命中 `1+ln(tf)`，章节名命中 +0.5，单字命中 0.3，按查询词数平方根归一化）→ 取 topK=4；
3. 组装引用列表（chunkId/章节/来源/摘要 120 字）；
4. 在线模式：`streamText` 以防幻觉系统提示词流式生成；离线模式：抽取式回答（教材原句摘录 + 参考章节）；LLM 调用异常自动降级为离线抽取式回答；
5. 响应流中**引用数据部件先于正文写入**，前端"参考章节"与可展开"引用片段"随即渲染，实现可溯源。

**路径推荐链路**：学生勾选掌握 → `POST /api/mastery`（add/remove/set 三种动作，zod 校验）→ `GET /api/path/{studentId}` 触发 `computeRecommendations` 图遍历 → 前端编号列表实时刷新。

## 四、模块详细设计

### 4.1 文档解析模块（`src/services/document.service.ts`）

**职责**：把上传的二进制文件变为"干净、带章节结构的文本块"，是全链路质量的起点。

- **类型检测** `detectFileType`：仅接受 `.pdf`/`.txt`，其余在路由层即拒绝（422），前端文件选择框同步限定 `accept`。
- **PDF 解析**：`pdf-parse` 从 `pdf-parse/lib/pdf-parse.js` 子路径引入（避开其主入口在构建期读取测试 PDF 的调试行为，已在 Next 打包配置中排除）；空文件直接返回空文本。
- **TXT 解码** `decodeText`：先按 UTF-8 解码并去 BOM；若结果含替换符 U+FFFD（GBK 教材被误按 UTF-8 解码的典型特征）则用 `TextDecoder('gbk')` 重新解码，解码器不可用时回退 UTF-8 结果。该机制针对性解决国内教材常见的 GBK 编码问题，有专项单元测试覆盖。
- **文本清洗** `cleanText`：统一换行符；去除换页符/零宽字符；过滤独立成行的页码（兼容 `12`、`3/45`、`- 12 -` 等形态）；压缩行内多余空白与 3 个以上连续空行。
- **章节切分** `splitByChapter`：正则识别"第X章/节/讲/部分（可带标题）"与"数字编号标题"两类形态；全文无标题时整体归入"全文"单章节，保证切块永不失败。
- **切块** `chunkText`：章节内按空行分段、段落打包至目标块大小（RAG 默认 800 字，抽取场景传 1600 字），**尽量不拆散段落**；超长单段按中文句号/问叹号边界切句再打包。每块携带 `chapter` 元信息，供检索加成与引用展示。

**设计考量**：切块粒度是抽取质量与检索召回的共同上游——太大则 LLM 抽取遗漏与 60s 预算压力增大，太小则语义不完整。800/1600 双粒度是按"一章内容 ≥20 个知识点"的赛题基准与 DeepSeek 上下文实测调定的，并经 `tests/unit/document.service.test.ts` 8 个用例固定行为。

### 4.2 知识抽取与关系构建模块（`src/lib/ai/`）

**抽取流水线**（`extract-knowledge.ts`）：

- 常量预算：`MAX_EXTRACTION_CHUNKS = 6`（参与抽取的块上限）、`MAX_KNOWLEDGE_POINTS = 80`（总量防跑飞）、`MAX_CONCURRENCY = 3`（并发限流，避免模型 429）；单块失败经 `Promise.allSettled` 跳过不中断整体（赛题明确"允许一定冗余和错误"）。
- 结构化输出：`schemas.ts` 用 zod 定义知识点（名称/一句话定义/章节/难度 1-5）与关系 schema，关系类型 `z.enum(['PREREQUISITE','CONTAINS','RELATED'])` **在协议层就限定**只允许三类（对应赛题"包含/前置/相关"）；`temperature = 0.2` 追求稳定。
- 合并去重：按名称归一化（去空白）`normalizeName` 去重，保留首次出现；知识点 id 由名称派生，天然幂等。
- **离线演示模式**：`isLLMConfigured()` 为假时返回内置《数据结构》演示数据集（`demo-dataset.ts`，**37 个知识点、51 条关系**，覆盖 7 章；其中关系 PREREQUISITE 29 / CONTAINS 12 / RELATED 10），保证零 Key 环境全流程可演示、e2e 可验证"≥20 个知识点"的赛题指标。

**关系清洗**（`extract-relations.ts` 三重过滤）：类型白名单过滤（`normalizeRelationType`）→ 端点存在性校验（source/target 必须是已入库知识点）→ 自环与重复去除。三层防线确保图数据拓扑合法， Cypher 写入不会因悬空端点报错。

**提示词工程**（`prompts.ts`，完整记录见 `docs/prompt-engineering.md`）：抽取系统提示词约束"只抽取教材中真实出现且值得作为独立教学单元的知识点""名称去重""一句话定义"；问答系统提示词 `buildQASystemPrompt` 注入检索上下文并要求"严格只根据教材内容回答、教材未涉及则明确拒答、结尾标注参考章节"。

### 4.3 图存储模块（`src/lib/db/graph-store.ts`）

**GraphStore 接口**（14 个方法，全部按 `courseId` 隔离，天然支持多课程）：`upsertKnowledge`（幂等）、`buildGraph`（单事务批量建图）、`getGraph`（返回 ECharts 直接可渲染的 nodes+edges）、`listKnowledge`、`getKnowledgeById`、`addKnowledge`、`updateKnowledge`（PATCH 语义，仅改传入字段）、`deleteKnowledge`（级联删关联关系）、`addRelation`（幂等）、`deleteRelation`、`getRelations`、`getPrerequisiteRelations`（路径推荐专用）、`countKnowledge`、`kind` 标识。

**双实现**：

- `Neo4jGraphStore`：neo4j-driver 5.x，Cypher 参数化查询防注入；知识点/关系建唯一索引；`buildGraph` 用事务批量 `MERGE`（幂等 upsert 语义）。
- `JsonGraphStore`：`data/store/` 下 JSON 文件原子读写（`json-file.ts`：临时文件写完再替换），同样实现全部幂等语义——**两套实现行为对齐，业务层零感知**。

**工厂与降级**（`getGraphStore`）：`GRAPH_STORE=json/neo4j` 强制指定；`auto`（默认）时若 Neo4j 三项配置齐全且 `verifyConnectivity()` 探测成功则用 Neo4j，否则打日志降级 JSON。工厂结果做进程内单例缓存（`globalThis` 挂载，dev 热重载安全；失败时清除缓存允许重试）。

**为什么这是全系统最重要的决策**：赛题允许"轻量级方案"，但评审机器大概率没有 Neo4j。把存储做成接口 + 双实现 + 自动降级后，"生产规格"（真实图数据库）与"零配置可评审"两个目标同时达成，且为答辩时演示 Neo4j 切换留好了口子。

### 4.4 RAG 智能问答模块（`src/services/rag.service.ts` + `src/app/api/qa/route.ts`）

**语料管理**：上传时 `saveChunks` 按 `courseId` 分组**整体覆盖**写入 `chunks.json`（重传同课程替换而非追加，防语料膨胀）；进程内单例缓存。多课程问答语料天然隔离。

**检索算法**（零向量库依赖）：

- 分词 `tokenize`：中文按**相邻双字（bigram）**、英文/数字按连续串、全部小写。bigram 对中文检索的召回显著优于逐字切分，且无需词典——"循环链表"会生成"循环/环链/链表"三个双字词，问句"链表的循环形式"能命中其中两个。
- 辅助信号 `tokenizeUnigrams`：单字集合，解决"问句措辞与原文不一致"（如问"特点"、原文写"特性"）时双字全落空的召回问题。
- 打分 `scoreChunk`：每个查询词命中计 `1 + ln(词频)`（次线性抑制长文档堆频）；**章节名命中 +0.5**（学生提问常含章节线索）；单字命中 +0.3（低权重兜底，防噪声主导）；总分除以 `√查询词数` 做长度归一化。取 topK（默认 4，`RAG_TOP_K` 可调）；若全块零分仍返回前 topK 块作为上下文，让 LLM 能据此回答"教材中未涉及"。

**生成与防幻觉**：在线模式 `streamText`（temperature 0.3）+ 防幻觉系统提示词（只依据教材、未涉及明确拒答、结尾标注参考章节）；离线模式 `extractiveAnswer` 按句子级打分挑出与问题最相关的 2-3 句教材原句并附参考章节；LLM 调用异常（网络/限流）自动降级离线抽取式回答，**问答功能永不 500**。

**流式与引用先行**：`/api/qa` 用 AI SDK 流式协议，`references` 作为数据部件**先于正文**写入响应流（`A10UIMessage` 类型将 references 声明在 message metadata 中），前端"参考章节"徽标与可展开"引用片段"（120 字摘要）即刻呈现，学生可点开核对原文——这是"可溯源、抗幻觉"体验的关键。

### 4.5 学习路径推荐模块（`src/services/path.service.ts`）

**掌握状态持久化**：`mastery.json` 按"学生 ID × 课程 ID"复合键隔离（`course.service.getMastery/setMastery`），支持 add/remove/set 三种动作（zod 校验），支撑多课程互不干扰的进度管理。

**推荐算法 `computeRecommendations`**（纯函数，四步）：

1. 构建前置索引：`target → [source…]`（PREREQUISITE 关系语义为 source 先修 → target 后学），端点不在课程内的关系直接忽略；
2. **候选集** = 未掌握，且全部前置均已掌握的知识点（无前置的知识点天然候选，保证冷启动可开始）；
3. **解锁价值**：模拟"学完该候选"后，有多少个未掌握知识点的前置条件将全部满足——优先学"承上启下"的枢纽知识点；
4. **三重排序**：解锁价值降序 → 难度升序 → 章节升序（`localeCompare('zh-CN')`，"第1章"排在"第2章"前）。

输出前 `limit`（默认 3）条，每条附自然语言推荐理由（"前置知识「线性表、栈」已掌握"/"无前置依赖，可以直接开始学习"）。复杂度 O(V+E)，百节点级课程瞬时完成，完全符合赛题"允许简单图遍历、不要求机器学习模型"的定位。纯函数设计使排序行为被 `tests/unit/path.service.test.ts` 4 个用例精确固定。

**展示**：`PathList` 以编号有序列表呈现学习先后顺序（知识点 + 章节/难度 + 推荐理由 + 快捷"标记已掌握"），勾选后推荐实时刷新，形成"学→勾→新推荐"闭环。

## 五、关键工程决策

以下决策均经过"备选方案对比 → 依据赛题约束取舍 → 测试固化行为"的过程，是本方案工程性的集中体现。

### 5.1 GraphStore 接口化 + 自动降级

- **问题**：赛题推荐 Neo4j，但评审/演示环境往往无 Neo4j；反之只用 JSON 文件又显得工程规格不足。
- **决策**：抽象 14 方法 `GraphStore` 接口，Neo4j（Cypher）与 JSON 文件双实现行为对齐；`GRAPH_STORE=auto` 时启动探测连通性，失败自动降级 JSON 并打日志。
- **收益**：零配置可评审 + 可演示真实图数据库两个目标兼得；业务层只依赖接口，切换存储零改动；两种实现都被同一套服务层代码路径覆盖测试。

### 5.2 bigram 词频检索替代向量库

- **问题**：赛题 RAG 路线通常隐含向量数据库（embedding + 相似度），但向量库部署是评审环境的额外负担，且小规模语料（单课程数十至数百块）上向量检索优势不明显。
- **决策**：中文 bigram + 英文单词 + 单字低权重兜底的词频打分检索，公式 `Σ(1+ln tf) + 0.5×章节命中 + 0.3×单字命中`，按 `√查询词数` 归一化。
- **收益**：零外部依赖、行为完全确定可单测（6 个检索专项用例）、中文召回质量经问答测试集 Q1-Q8 离线验证；embedding 语义检索列入改进方向而非当前阻塞项。

### 5.3 离线演示模式作为"一等公民"

- **问题**：没有 LLM Key 时系统是否就"死"了？
- **决策**：`isLLMConfigured()` 为假时，抽取返回人工预标注的内置《数据结构》数据集（37 知识点/51 关系），问答返回教材原句抽取式回答；上传响应携带 `demoMode: true` 标志，前端明示"当前为离线演示数据"。
- **收益**：评审零 Key 可跑通全部流程；e2e 测试因此可在 CI 离线稳定运行；`demoMode` 标志保证了"演示数据"与"真实抽取"永不混淆——这是材料诚实性原则在代码层的落实。
- **边界**：演示数据集是人工预标注的，其"准确率 100%"不代表大模型抽取能力，材料中从不引用该数字作为抽取质量证据。

### 5.4 引用先行的流式问答

- **决策**：`/api/qa` 响应流中 `references` 数据部件先于正文写入。
- **收益**：学生的问题刚发出，"参考章节"徽标即出现（检索耗时毫秒级），流式正文随后逐字呈现——感知延迟远低于赛题 15s 上限；引用可展开核对原文，抗幻觉体验完整。

### 5.5 抽取预算的三重控制（60 秒指标）

- **决策**：块数上限 6（`MAX_EXTRACTION_CHUNKS`）× 单块 1600 字 → 参与抽取的文本量封顶约 9600 字；并发 3；单块失败 `allSettled` 跳过；知识点总量上限 80。
- **收益**：即使教材全文 10 万字，抽取调用量也恒定有界，60 秒预算可控；每次上传返回 `timing`（解析/抽取/合计毫秒）供逐次核查，实测汇总待真实 Key 回填。

### 5.6 中文编码鲁棒性（GBK 自动回退）

- **决策**：TXT 按 UTF-8 解码后检测 U+FFFD 替换符，出现即用 GBK 二次解码。
- **收益**：国内教材常见的 GBK/GB2312 编码文件开箱即用；该行为有专项单元测试固化，评审用自备教材上传不会因编码问题翻车。

### 5.7 pdf-parse 子路径引入

- **决策**：`import pdfParse from 'pdf-parse/lib/pdf-parse.js'`，并在 Next 打包配置中显式排除。
- **原因**：pdf-parse 主入口（index.js）在被打包工具引用时会尝试读取其自带的测试 PDF（调试模式行为），在 Next.js 构建期报错；走 lib 子路径绕开该入口是社区验证过的标准做法。

### 5.8 纯函数化可测性设计

- **决策**：推荐算法 `computeRecommendations`、权限判定 `decideTeacherAccess`、分词/打分/清洗/切块等全部做成纯函数，I/O 在边缘薄层。
- **收益**：18 个单元测试无需 mock 数据库/网络即可覆盖全部核心算法；行为回归有保障。

| `GET /api/health` | 公开 | 健康检查 + 配置就绪状态 | → Neo4j/LLM 配置状态（不泄露密钥） |

（另含 NextAuth 标准路由 `/api/auth/[...nextauth]`。错误响应统一 `ApiResponse.error`，权限不足按 401/403 语义区分。）

## 十、已知限制与改进方向（如实）

| # | 已知限制 | 原因 | 改进方向 |
| --- | --- | --- | --- |
| 1 | 仅支持 PDF/TXT，未支持 DOCX/Markdown | 赛题要求"四种选两种"，PDF+TXT 已达标；DOCX 解析需引入 mammoth 等 | 增加 DOCX（mammoth）/MD（按标题层级）解析器，`detectFileType` 白名单扩展即可，架构无需改动 |
| 2 | 抽取准确率无在线实测数字 | 未接入真实 LLM Key（诚实性原则：宁缺毋假） | 按 `docs/extraction-accuracy-report.md` 流程接入 DeepSeek/通义实测回填；错误模式分析已预置 |
| 3 | 知识消歧为词面级（归一化去重），无语义级同义合并 | embedding 依赖外部 API，与"零依赖可评审"冲突 | 接入 Key 后为知识点名称生成向量，相似度阈值合并 + 人工确认队列 |
| 4 | 路径推荐为编号列表，未做图形化路径连线 | 赛题仅要求"推荐结果的可视化路径展示"，列表 + 理由已覆盖主旨；图形连线与 ECharts 树图集成在时间盒内让位于稳定性 | 在 `PathList` 中以 ECharts tree/linear 图呈现推荐链 |
| 5 | 上传为同步处理，未做分步轮询进度条 | 同步链路让耗时分解（timing）可一次性返回、链路可测性最好；60s 预算内体验可接受 | 改造为"上传即返回任务 id + 轮询/SSR 进度"异步任务模型 |
| 6 | 单用户演示级并发，未做多租户/水平扩展设计 | 赛题面向单机评审场景 | JSON 存储换 Neo4j（已支持）+ 会话横向扩展 |
| 7 | 图谱截图待人工截取 | 不虚构截图（诚实性原则） | 运行系统截图，或由演示视频呈现 |
