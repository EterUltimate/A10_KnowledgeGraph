# A10 知识图谱系统 · 安全审计报告（Security Audit Report）

> **范围**：`EterUltimate/A10_KnowledgeGraph` main 分支截至 v1.0 交付候选的所有代码、依赖、配置与运行环境。
> **方法**：OWASP Top 10 (2021) 逐条比对 + LLM 应用专项 + GitHub Advanced Security 工具链自动化 + 人工审阅。
> **工具**：CodeQL (SAST) · gitleaks (密钥扫描) · npm audit + Dependabot (依赖) · Playwright e2e (功能回归) · 契约测试 (鉴权/校验/错误码)。
> **结论**：高危项 0；中危项 0；低危/建议项 5 项（均已缓解或列入路线图）。系统达到商业交付安全基线。

## 0. 风险等级说明

| 级别 | 定义 | 处置要求 |
| --- | --- | --- |
| 🔴 高危 | 可被外部未授权方直接利用造成数据泄漏 / 服务不可用 / RCE | **发布前必须修复** |
| 🟠 中危 | 需一定前提条件（如需登录、需内网）方可利用 | **发布前应修复** |
| 🟡 低危 | 影响可控或利用门槛高 | 建议修复，可延后 |
| ℹ️ 信息 | 非漏洞，属最佳实践提示 | 记录 |

## 1. OWASP Top 10 逐条审计

### A01 失效的访问控制（Broken Access Control）— ✅ 已缓解

- **风险面**：教师端 `/api/knowledge` `/api/relation` `/api/course/upload` 的写接口若未鉴权，任何人可增删改知识图谱。
- **实施**（A-1，PR #14）：
  - `src/auth.ts` 采用 Auth.js Credentials Provider，教师/学生两种角色，会话 JWT 存储。
  - `src/middleware.ts`（Edge 层）路由级拦截：`/teacher/*` 未登录跳 `/login`，非教师跳 `/login?error=forbidden`；教师写 API 直接返回 401/403。
  - `src/lib/auth-guard.ts` `requireTeacher()`（Node 层）二次校验，返回 null 放行 / 401 / 403。
  - 纯判定 `decideTeacherAccess` 抽至 `src/lib/auth-roles.ts`，3 例单测覆盖。
- **契约测试证据**：`tests/unit/api-contract.test.ts` 22 例中，所有写接口反例（未登录、学生越权）均断言返回 401/403。
- **残余风险**：无。**评分：合格**。

### A02 加密机制失效（Cryptographic Failures）— ✅ 已缓解

- **敏感数据清单**：LLM API Key、Neo4j 密码、`AUTH_SECRET`（JWT 签名密钥）、学生掌握状态。
- **实施**：
  - 所有密钥经 `.env` 注入，`.gitignore` 排除 `.env*`（仅 `.env.example` 入库）；`.dockerignore` 亦排除，不入镜像层。
  - `AUTH_SECRET` 强制：生产 `NODE_ENV=production` 下缺失即启动失败（`src/lib/auth-env.ts`）。
  - Neo4j 走 `bolt://` 内网通信；Vercel/AuraDB 场景由平台提供 TLS。
  - 密码不入库：学生掌握状态按 `studentId::courseId` 存储，无凭证字段。
  - `.github/workflows/security.yml` + gitleaks 全历史扫描，防意外提交。
- **残余风险**：**部署文档 `docs/deployment.md` 第六节明确要求生产环境必须替换默认 `AUTH_SECRET` 与 `DEMO_*_PASSWORD`**；若使用 Docker Compose 默认密码，属部署侧风险。
- **建议**：Docker Compose 生产部署时通过 `.env` 强制覆盖默认；`docker-compose.yml` 已用 `${VAR:-default}` 语法保留覆盖能力。

### A03 注入（Injection）— ✅ 已缓解（多层次防护）

**（1）Cypher 注入**（Neo4j）：
- **风险面**：关系类型、标签、属性键在 Cypher 中**不能参数化**（`$type` 不支持），必须字符串内插。若上游校验遗漏，即构成注入。
- **实施**（PR #12 审查 + A-5，PR #16）：
  - `src/lib/db/graph-store.ts` `normalizeRelationType()` 白名单校验，非法返回 null。
  - `src/lib/db/neo4j-store.ts` `assertRelationType()` 运行时强校验：三处内插点（`buildGraph` / `addRelation` / `deleteRelation`）在拼装 Cypher 前必须调用，非法抛错。
  - 其他标识符（节点标签 `Knowledge`、属性键）全部硬编码常量，无动态拼接。
- **验证**：`tests/unit/hardening.test.ts` 11 例中覆盖非法关系类型拒绝路径。

**（2）NoSQL/JSON 注入**：
- JSON 存储按 `courseId` 与 `studentId::courseId` 复合键读写，键来源为 zod 校验后的字符串，无原型污染面。
- **建议**：未来接入 SQLite/Postgres 时使用参数化查询（`better-sqlite3` 原生支持）。

**（3）命令注入 / XSS**：
- 无 `child_process` / `eval` / `Function` 构造。
- React 默认转义；`dangerouslySetInnerHTML` 未使用；ECharts tooltip 通过 `formatter` 函数返回文本，非 HTML 注入。

- **残余风险**：无。**评分：合格**。

### A04 不安全设计（Insecure Design）— ✅ 已考虑

- **威胁建模**（简要）：
  - 上传文件为最大攻击面 → 已限文件类型（PDF/TXT）、大小（20MB）、魔数校验（防伪造扩展名）、解析异常不崩服务。
  - LLM 抽取输出为二次信任边界 → zod schema 强制结构 + 关系三重清洗 + 提示词工程约束「严格基于教材」。
  - 学生数据为隐私资产 → 按 `studentId::courseId` 隔离；无 PII（姓名/身份证等）字段。
- **加分项**：赛题「教师手动修正图谱」→ 通过鉴权 + 审计（`console.log` 日志）实现，见 A-1。
- **改进路线图**（见 `docs/extraction-accuracy-report.md` 第四节）：embedding 同义合并、Prompt 注入防护强化。

### A05 安全配置错误（Security Misconfiguration）— ✅ 已缓解

- **默认安全**：
  - 未配 LLM Key → 离线演示模式（不发起外网调用）。
  - 未配 Neo4j → 自动降级 JSON 存储（`GRAPH_STORE=auto`），不中断服务。
  - 未配 `AUTH_SECRET` 且 `NODE_ENV=production` → 启动失败（强制设置）。
- **最小权限**：Docker 容器 `USER node`（非 root）运行。
- **关闭调试信息**：`.next/standalone` 生产构建不含 sourcemap；错误响应 `src/lib/http.ts` 统一格式，不泄漏堆栈。
- **CSP / CORS**：Next.js 默认同源；本应用无跨域需求。若接入外部前端，应在中间件加 CORS 白名单（当前无该需求，不引入）。
- **建议**（ℹ️ 信息项）：生产环境如需强制 HTTPS，可在反代或 `next.config.mjs` 中启用 HSTS header。

### A06 易受攻击与过时的组件（Vulnerable Components）— ✅ 持续防护

- **工具**：Dependabot（`.github/dependabot.yml`，每周检查 npm + github-actions）+ `npm audit`（CI security job）+ CodeQL。
- **当前基线**（截至本审计）：`npm audit` **无高危**；GitHub Security Overview 无未处理 alerts。
- **依赖选择原则**：
  - `neo4j-driver`（官方）、`next-auth` v5 beta（业界主流）— 高活跃维护。
  - `pdf-parse`（历史久，含调试入口风险）— 已 `serverExternalPackages` 排除并走 `lib/pdf-parse.js` 子路径，规避 `index.js` 的自动文件读取行为。
- **建议**（🟡 低危）：`next-auth` v5 目前为 beta；发布前建议锁定 RC 或稳定版本号，避免 breaking change。

### A07 身份识别与认证失效（Identification & Auth Failures）— ✅ 已缓解

- **会话管理**：Auth.js JWT 策略（`session.strategy: 'jwt'`），HTTPOnly Cookie（默认），`sameSite: 'lax'`。
- **凭据保护**：演示账号密码走 `.env`，生产部署必须替换；不做真实注册功能（赛题无此需求）。
- **暴力破解**：登录端点 `/api/auth/*` 走 NextAuth 内置；如需更严格限流，可在 `middleware.ts` 中额外加令牌桶（当前 `checkRateLimit` 已可用于此路径）。
- **建议**（🟡 低危）：生产部署可加登录失败次数上限（Auth.js 支持 `signIn` callback 拦截）。

### A08 软件与数据完整性失效（Integrity Failures）— ✅ 已缓解

- **CI 构建可重现**：`npm ci` + lockfile 严格匹配。
- **镜像签名**（可选）：目前 `release.yml` 推 GHCR 但未做 cosign 签名。若面向企业客户发布，应加签名步骤（路线图）。
- **依赖锁定**：`package-lock.json` 入库；Dependabot 更新通过 PR 走人工 review + CI。
- **前端资源**：Next 自动 fingerprint，无 CDN 篡改风险。

### A09 日志与监控失效（Logging & Monitoring Failures）— ✅ 已实现

- **结构化日志**：`console.log` 分级：`[store]` / `[neo4j]` / `[llm]` / `[extractKnowledge]` / `[extractRelations]` / `[mastery-store]` 等模块前缀。
- **健康检查**（A-3）：`GET /api/health` 无鉴权开放，返回三项自检状态、配置概览、uptime、latency；Docker HEALTHCHECK 与 compose healthcheck 均已配置。
- **审计事件**：教师写操作在 `src/lib/auth-guard.ts` + route handler 中有 `console.info` 记录（可扩展 pino）。
- **建议**（ℹ️ 信息项）：接入 OpenTelemetry / Sentry 做全链路可观测性；本版本不引入以保持依赖精简。

### A10 服务端请求伪造（SSRF）— ✅ 已缓解

- **风险面**：`LLM_BASE_URL` 可由环境变量注入，攻击者若获得部署权限可指向内网。
- **实施**（A-5，PR #16）：`src/lib/ai/provider.ts` 内置 `validateBaseUrl` 启动时校验：① 强制 https（本地调试可 `LLM_ALLOW_INSECURE_BASEURL=1` 放开）；② 正则拒绝内网/回环主机名（`localhost` / `127.*` / `10.*` / `192.168.*` / `172.16-31.*` / `::1` 等）一防 SSRF；本地推理（Ollama 等）可显式 `LLM_ALLOW_LOCAL_LLM=1` 开启。
- **残余风险**：企业内网自建 LLM 网关的开启属部署方信任判断；默认已安全。

## 2. LLM 应用安全专项

| 风险 | 缓解 |
| --- | --- |
| **提示注入**（Prompt Injection）—— 上传的教材文本中嵌入恶意指令 | ①`KNOWLEDGE_EXTRACTION_SYSTEM_PROMPT` 明确"仅抽取教材真实出现的知识点"；②`buildQASystemPrompt` 约束"严格只根据教材内容回答"；③抽取输出经 zod schema 强制结构（name/definition/chapter/difficulty），非结构内容一律拒绝；④问答流仅返回 text + data-references，不返回工具调用 |
| **数据泄漏** —— 用户提问被 LLM 记忆并回吐 | ①仅 DeepSeek/通义这类企业级 API，合同上承诺不用于训练；②教材内容为课堂资料，敏感度低；③不上传密钥等机密 |
| **模型输出不安全内容** —— LLM 生成违规文本 | ①`streamText` 输出走 React 转义渲染，不执行 HTML；②模型供应商侧内容审核（DeepSeek 内置）；③教师端可编辑/删除知识点，形成人工闭环 |
| **拒绝服务**（DoS）—— 长文本无限抽取 | ①抽取分块上限 `MAX_EXTRACTION_CHUNKS=6`；②知识点上限 `MAX_KNOWLEDGE_POINTS=80`；③单次上传 `MAX_FILE_SIZE=20MB`；④限流（`src/lib/rate-limit.ts`）默认按 IP 令牌桶 |

## 3. 数据隐私声明

- **收集范围**：教师上传的教材文本、知识点抽取结果、关系抽取结果、学生 ID（前端 localStorage 生成，无 PII）、课程 ID、学生掌握状态（勾选记录）。
- **不收集**：姓名、身份证、手机号、邮箱、设备指纹、地理位置。
- **存储位置**：
  - 图数据（Knowledge 节点 / 关系）→ Neo4j（可选）或 `data/store/graph.json`
  - 课程注册表 → `data/store/courses.json`
  - 学生掌握状态 → `data/store/mastery.json`
  - RAG 语料 → `data/store/chunks.json`
- **数据保留**：系统运行期间持久保留，无自动过期；`docker compose down -v` 或 `rm -rf data/store/*` 可清库。
- **数据出境**：LLM 走第三方 API（DeepSeek/通义），教材内容会发送至模型供应商处理。部署方应根据自身合规要求选择供应商。
- **教师审计**：教师可查看/编辑/删除任意课程的知识点与关系；无学生个人身份关联（掌握状态按 `studentId::courseId` 键，`studentId` 为前端匿名 UUID）。
- **合规**：赛题项目本身无实际生产用户；如部署至学校生产环境，须遵循《个人信息保护法》与所在学校的数据治理政策。
