## 2 架构设计目标与约束

### 2.1 赛题约束

| # | 约束 | 来源 |
| --- | --- | --- |
| C1 | 支持 ≥2 种文档格式解析（本系统取 PDF + TXT） | 赛题「技术要求」 |
| C2 | 单课程一章自动抽取知识点 ≥20 个 | 赛题「技术要求」 |
| C3 | 关系类型 ≥3 种（前置 / 包含 / 相关） | 赛题「技术要求」 |
| C4 | 抽取准确率 ≥70%（允许一定冗余与错误，需说明改进方向） | 赛题「技术要求」 |
| C5 | 解析+抽取 ≤60s；问答 ≤15s；普通电脑可运行 | 赛题「性能要求」 |
| C6 | 多课程管理（≥2 门独立课程） | 赛题「功能完整性」 |

### 2.2 架构级非功能目标

| 目标 | 设计落地 |
| --- | --- |
| **零配置可评审** | 存储可无 Neo4j、LLM 可无 Key，全部自动降级；部署仅 `npm install → build → start` |
| **可替换性** | 存储 / LLM 供应商均可替换，不触碰业务代码 |
| **数据正确性** | zod 运行时校验 + 关系三重清洗，禁止脏数据入图 |

## 3 总体架构

### 3.1 技术选型

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 前端 | React 19 + Next.js 15（App Router）+ TypeScript | 全栈同构，页面与 API 同仓单进程部署 |
| 大模型 | Vercel AI SDK v5（`ai` + `@ai-sdk/openai-compatible`） | 一套代码兼容 DeepSeek / 通义；`generateObject` 结构化输出、`streamText` 流式 |
| 图数据库 | Neo4j Community（bolt）+ JSON 文件兜底双引擎 | 抽象接口后双实现可切换，auto 模式探测降级 |
| 可视化 | ECharts 5 Graph 力导向图 | `roam` 缩放拖拽、关系分色、节点大小映射难度 |
| 文档解析 | pdf-parse（Node）+ 自研 TXT 解码 | 同语言栈，避免跨进程；GBK 自动回退 |
| 检索 | 自研 bigram+单字词频打分（零向量库） | 中文召回好、零依赖、行为确定 |

### 3.2 分层架构（图 1）

![](..\architecture\01-系统总体架构图.png)

**分层依赖严格单向**：页面组件 → API 路由 → 服务层 → 存储层 / AI 层 → 基础设施。这是全系统最重要的架构约束。

### 3.3 双模式设计（图 1 右侧注解）

| 模式 | 触发 | 抽取行为 | 问答行为 |
| --- | --- | --- | --- |
| 在线模式 | `LLM_API_KEY` 已配 | `generateObject` + zod 真实抽取 | `streamText` 流式生成 |
| 离线演示模式 | 未配 Key（含占位值 `your_api_key_here`） | 返回内置《数据结构》演示数据集 | 教材原句抽取式回答 |

存储侧对称地有 `GRAPH_STORE=auto`（探测 Neo4j，失败降级 JSON）/ `neo4j` / `json` 三种策略。双维度的降级保证「零配置可评审」与「生产规格」两个目标同时成立。

## 4 模块划分（图 5）

![](..\architecture\05-模块组件图.png)

### 4.1 服务层（src/services，业务编排）

| 模块 | 职责 | 关键函数 |
| --- | --- | --- |
| `document.service` | 类型检测、PDF/TXT 解析、清洗、章节切块 | `detectFileType` / `parseFile` / `cleanText` / `splitByChapter` / `chunkText` |
| `rag.service` | 检索打分、引用构建、离线兜底回答 | `tokenize` / `scoreChunk` / `retrieve` / `extractiveAnswer` |
| `path.service` | 前置图遍历推荐 | `computeRecommendations`（纯函数） |
| `graph.service` | 图谱读写编排 | 对 GraphStore 接口的二次封装 |
| `course.service` | 课程注册表、掌握状态 | `createCourse` / `listCourses` / `getMastery` / `setMastery` |

### 4.2 AI 层（src/lib/ai）

| 模块 | 职责 |
| --- | --- |
| `extract-knowledge` | 知识点实体抽取：分块并行 `generateObject`，名称归一化去重 |
| `extract-relations` | 关系抽取 + 三重清洗（类型白名单 → 端点存在性 → 自环/重复） |
| `schemas` | zod 结构化约束；关系类型 `z.enum` 在协议层限定三类 |
| `prompts` | 抽取 / 问答系统提示词（防幻觉约束） |
| `provider` | OpenAI 兼容客户端构造（DeepSeek / 通义切换点） |
| `demo-dataset` | 内置《数据结构》演示数据集（37 知识点 / 51 关系） |

### 4.3 存储层（src/lib/db）

**GraphStore 接口**：

```
upsertKnowledge · buildGraph · getGraph · listKnowledge · getKnowledgeById
addKnowledge · updateKnowledge · deleteKnowledge · addRelation · deleteRelation
getRelations · getPrerequisiteRelations · countKnowledge · kind
```

| 实现 | 技术 | 特点 |
| --- | --- | --- |
| `Neo4jGraphStore` | neo4j-driver 5.x，Cypher 参数化查询 | 事务批量 `MERGE`（幂等）；唯一索引；生产规格 |
| `JsonGraphStore` | `data/store/*.json` 原子读写 | 幂等 upsert；零配置兜底；行为与 Neo4j 实现对齐 |

**工厂 `getGraphStore()`**：进程内单例（`globalThis` 挂载，dev 热重载安全）；auto 模式探测连通性，失败降级 JSON 并打日志；失败清除缓存允许重试。

### 4.4 基础设施（src/lib）

| 模块 | 职责 |
| --- | --- |
| `config.ts` | `.env` 集中读取校验，业务代码不直接访问 `process.env` |
| `http.ts` | 统一响应封装 `ApiResponse<T>` |
| `auth-guard.ts` / `auth-roles.ts` | 权限判定 `decideTeacherAccess`（纯函数，401/403 语义） |
| `neo4j.ts` | 驱动单例 + `verifyConnectivity` 连通性验证 |
| `json-file.ts` | 原子 JSON IO（临时文件写完再替换） |
| `middleware.ts` | 路由级鉴权守卫 |

## 5 核心流程设计（图 3）

![](..\architecture\03-核心流程时序图.png)

### 5.1 上传建图链路（同步，`POST /api/course/upload`）

1. 路由校验文件类型（`.pdf`/`.txt` 白名单）与大小（≤20MB），注册/更新课程；
2. `parseFile`：PDF 走 pdf-parse，TXT 按 UTF-8 解码、出现 U+FFFD 自动回退 GBK；
3. `cleanText`（去页码/页眉/控制字符）→ `chunkText` 章节感知切块（RAG 800 字 / 抽取 1600 字）；
4. `extractKnowledge`：离线返回演示数据集；在线按块并行调用 LLM（并发 3、块数上限 6、知识点上限 80）；
5. `extractRelations`：三重清洗；
6. `GraphStore.buildGraph` 单事务批量写入；`saveChunks` 按 `courseId` 覆盖写 RAG 语料；
7. 返回 `UploadResult`（知识点数 / 关系数 / 文本块数 / `timing{parseMs,extractMs,totalMs}` / `demoMode`）。

### 5.2 RAG 问答链路（流式，`POST /api/qa`）

1. `rag.retrieve`：问句分词（中文 bigram + 英文单词 + 单字辅助）→ 逐块打分（`1+ln(tf)`，章节名命中 +0.5，单字 0.3，按 `√查询词数` 归一化）→ 取 topK=4；
2. 组装引用列表（chunkId / 章节 / 来源 / 120 字摘要）；
3. 在线 `streamText` 流式生成；离线 / LLM 异常降级为教材原句抽取式回答；
4. **引用数据部件先于正文**写入响应流，前端即时渲染「参考章节」与可展开「引用片段」。

### 5.3 路径推荐链路（图遍历，`GET /api/path/[studentId]`）

1. 学生勾选掌握 → `POST /api/mastery`（add/remove/set，zod 校验）持久化；
2. `computeRecommendations`（纯函数，O(V+E)）：
   - 候选集 = 未掌握且全部 PREREQUISITE 前置已掌握（无前置者天然候选，保证冷启动）；
   - 排序 = 解锁价值降序 → 难度升序 → 章节升序（`localeCompare('zh-CN')`）；
3. 返回前 `limit`（默认 3）条，附自然语言推荐理由。

## 6 数据模型设计（图 4）

> 单一事实来源：`src/types/index.ts`。存储以 GraphStore 按 `courseId` 隔离；掌握状态按 `studentId×courseId` 复合键隔离。

![](..\architecture\04-数据模型ER图.png)

### 6.1 核心实体

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `KnowledgePoint` | id（名称派生，幂等）、name、definition、chapter、difficulty(1-5)、source?、courseId? | 知识点实体 |
| `Relation` | source、target、type | 端点指向课程内知识点名；type 仅三类 |
| `Course` | id、name、fileTypes[]、createdAt、knowledgeCount? | 课程注册表项 |
| `Student` | id、name、courseId? | 学生 |
| `MasteryState` | studentId、courseId、mastered[] | 复合键 (studentId, courseId) |
| `TextChunk` | id（`{courseId}-chunk{i}`）、courseId、content、chapter?、source? | RAG 语料块 |
| `PathRecommendation` | studentId、recommendations[]（{knowledge, reason}） | 推荐结果 |
| `QAReference` | chunkId、chapter?、source?、snippet(120 字) | 问答引用 |

### 6.2 关系基数

- Course **1 : N** KnowledgePoint / TextChunk / Student（按 `courseId`）
- Student **1 : N** MasteryState，Course **1 : N** MasteryState（复合键）
- KnowledgePoint **1 : N** Relation（source/target 自关联）
- TextChunk **1 : N** QAReference（按 `chunkId`）
- Student **1 : N** PathRecommendation；KnowledgePoint **N : N** PathRecommendation

### 6.3 传输对象（DTO）

`UploadResult`（含 timing + demoMode）、`ApiResponse<T>`（统一包装）、`QAResponse`（非流式）、`A10UIMessage`（流式：UIMessage + references 数据部件）、`GraphData`（ECharts 可渲染视图对象）。

## 7 接口设计

### 7.1 REST API 端点全表

| 方法与路径 | 权限 | 功能 |
| --- | --- | --- |
| `POST /api/course/upload` | teacher | 上传解析建图全链路 → `UploadResult` |
| `GET /api/course/list` | 登录 | 课程列表（含知识点计数） |
| `GET /api/graph/[courseId]` | 登录 | 课程图谱 → `GraphData` |
| `GET /api/knowledge` | 登录 | 知识点列表（按章节/名称排序） |
| `POST /api/knowledge` | teacher | 新增知识点（同名更新） |
| `GET /api/knowledge/[id]` | 登录 | 知识点详情 |
| `PATCH /api/knowledge/[id]` | teacher | 编辑（局部 patch） |
| `DELETE /api/knowledge/[id]` | teacher | 删除（级联删关联关系） |
| `GET /api/relation` | 登录 | 关系列表 |
| `POST /api/relation` | teacher | 新增/更新关系（白名单校验） |
| `DELETE /api/relation` | teacher | 删除关系 |
| `POST /api/qa` | 登录 | 流式问答（references 先行） |
| `GET/POST /api/mastery` | 登录 | 掌握状态读/写（add/remove/set） |
| `GET /api/path/[studentId]` | 登录 | 学习路径推荐 |
| `GET /api/health` | 公开 | 健康检查 + 配置就绪状态（不泄露密钥） |

（另含 `GET /api/auth/[...nextauth]` 标准路由。）

### 7.2 接口约定

- 统一响应包装 `ApiResponse<T>` = `{ success, data?, error? }`；
- 权限语义：未登录 401、角色不足 403、非法类型 422；
- 鉴权双层校验：`middleware.ts` 路由守卫 + API 内 `auth-guard.ts` 角色守卫；
- 全部路由经 `next build` 编译验证。

## 8 关键设计决策（ADR 摘要）

> 每项决策均经「备选方案对比 → 依据赛题约束取舍」。

| # | 决策 | 依据 | 收益 |
| --- | --- | --- | --- |
| ADR-1 | GraphStore 接口化 + auto 自动降级 | 评审环境大概率无 Neo4j，又需生产规格 | 零配置可评审 + 可演示真实图库，切换零改动 |
| ADR-2 | bigram 词频检索替代向量库 | 向量库是评审额外负担，小语料优势不明显 | 零外部依赖、行为确定、中文召回好 |
| ADR-3 | 离线演示模式作为一等公民 | 无 Key 系统不能「死」 | 零 Key 全流程可跑、离线稳定 |
| ADR-4 | 引用先行的流式问答 | 检索毫秒级，生成秒级 | 感知延迟远低于 15s，抗幻觉体验完整 |
| ADR-5 | 抽取预算三重控制 | 60s 指标 | 块数上限 6 × 并发 3 × 知识点上限 80，调用量恒定有界 |
| ADR-6 | GBK 自动回退 | 国内教材常见编码 | 自备教材上传不因编码翻车 |
| ADR-7 | pdf-parse 子路径引入 | 主入口构建期读测试 PDF 报错 | 绕开调试入口，构建稳定 |

## 9 部署架构（图 2）

![](..\architecture\02-部署架构图.png)

| 方案 | 组成 | 适用 |
| --- | --- | --- |
| 方案一 裸 Node | `npm install → build → start`，本地 JSON 存储 | 评审演示（零配置最快） |
| 方案二 Docker 单容器 | 多阶段构建（deps→build→run），volume 持久化 | 轻量对外部署 |
| 方案三 Docker Compose | next 容器 + Neo4j 容器 + 数据卷 | 需真实图库的生产 |
| 方案四 Vercel + AuraDB | serverless + 托管图库 + 环境变量 | 团队长期托管零运维 |

四方案共享同一套代码，仅通过 `.env`（`GRAPH_STORE` / `NEO4J_*` / `LLM_*`）与运行环境切换。
