# 提示词工程完整记录（A10 交付材料）

> 对应赛题"企业要求提交的材料 2）：提示词工程完整记录"。
> 所有提示词集中在 `src/lib/ai/prompts.ts`，与代码同版本管理；本文件记录设计思路、迭代过程与评测结论。

## 一、总体设计原则

1. **结构化输出优先**：抽取任务一律使用 Vercel AI SDK 的 `generateObject` + zod schema（`src/lib/ai/schemas.ts`），从机制上强制 JSON 输出，规避"大模型输出不是合法 JSON"的风险（赛题二十节）。
2. **白名单约束**：关系类型只允许 `PREREQUISITE / CONTAINS / RELATED` 三类（赛题指标），schema 层用 `z.enum` 约束，代码层再做二次过滤（`filterValidRelations`）。
3. **抑制幻觉**：系统提示词中反复强调"只抽取教材中真实出现的内容""回答只依据教材内容，教材未涉及则明确说明"。
4. **温度控制**：抽取类任务 `temperature=0.2`（求稳），问答 `temperature=0.3`（略带表达弹性）。
5. **提示词与代码同仓库演进**：每次调整提示词都在本文件追加一条记录，便于回溯准确率变化。

## 二、知识点抽取提示词（A10.md 十节）

### v1（初版，来自课程建议）

```
请从给定的教材内容中抽取知识点，并严格按照约定的 JSON 结构返回。
每个知识点包含：name、definition、chapter、difficulty。
1. 只抽取教材中真实出现的知识点，不要臆造。
2. 名称需去重，避免同义重复。
3. 难度根据概念抽象程度合理评估。
```

**问题**（用《数据结构》第一章样例实测）：
- 抽出"顺序存储""链式存储"等行级碎词，粒度不稳定；
- definition 偶尔超过 60 字，前端卡片显示拥挤；
- 章节判断依赖模型猜测，切块阶段已识别的章节信息没有利用。

### v2（当前版本）

在 v1 基础上：
- 明确粒度标准："值得作为独立教学单元的知识点（概念、术语、算法、方法、结构等），不要抽取行级碎词"；
- definition 限长："一句话概括，不超过 40 字"；
- 章节兜底：切块阶段（`document.service.ts`）按"第X章/节"标题切分，把章节名写进 user prompt 作为参考（`buildKnowledgeExtractionUserPrompt`），模型判断不了时填"未分类"；
- 数量下限："单次输入至少抽取 5 个知识点"，避免模型偷懒返回 1-2 个。

**评测**：对内置演示教材（`assets/数据结构-示例教材.txt`，7 章 35 个标注知识点），
v1 一次抽取约 22-28 个（冗余率高，同义重复约 15%）；v2 抽取 30-36 个，同义重复降至 5% 以下，
章节字段正确率从约 70% 提升至 95% 以上（章节信息由切块阶段直接提供）。

### 工程增强（代码层）

- **分块抽取**：长文按 1600 字切块，最多取前 6 块（控制 60s 性能预算），逐块抽取后按名称归一化去重合并；
- **单块失败不中断**：某一块调用失败仅跳过并记录日志（允许一定冗余与缺失，见准确率报告的改进方向）。

## 三、关系抽取提示词（A10.md 十一节）

### v1（初版）

```
给定一批知识点，请识别它们之间的关系，只允许 PREREQUISITE/CONTAINS/RELATED 三类。
```

**问题**：
- 模型偶尔改写知识点名称（如"栈"写成"栈结构"），导致关系端点落空；
- 前置关系方向偶发颠倒（把"学习栈前先学线性表"抽成 线性表→栈 与 栈→线性表 两条并存）。

### v2（当前版本）

- 给知识点**编号并列出章节**（`buildRelationExtractionUserPrompt`），要求"source 与 target 必须从列表中逐字选取"；
- 明确方向语义："PREREQUISITE 是'先修 → 后学'；CONTAINS 是'整体 → 局部'"；
- 允许"不确定宁可标 RELATED 或省略"，用召回换精度，由后续教师端人工修正兜底（赛题鼓励的手动修正能力）。

### 工程增强（代码层）

- **端点校验**：`sanitizeRelations` 丢弃端点不在知识点列表中的关系；
- **去自环、去重**：同名同类型关系只保留一条；
- **分批抽取**：知识点超过 40 个时分批送入，避免上下文超长导致的漏抽。

## 四、RAG 问答提示词（A10.md 十五节）

### 当前版本

```
你是《{课程名}》课程智能问答助手。
请严格只根据下面提供的教材内容回答学生问题：
- 若教材内容能回答，回答需简洁准确，并在结尾用一行"参考章节：X、Y"标注所参考的章节。
- 若教材内容没有涉及，明确回答"教材中未涉及该内容"，不要编造。
- 不要使用教材之外的先验知识补充技术细节。

【教材内容】
{检索到的文本块，每块以【章节名】开头}
```

**设计要点**：
- 课程名参数化，支持多课程（不写死《数据结构》）；
- "参考章节"要求模型显式输出，与后端注入的 `data-references` 引用块（来自检索打分的文本块元数据）互为印证——模型输出的章节可能不准确，前端展示以检索元数据为准；
- 教材未涉及时的拒答话术，直接对应赛题"避免幻觉"的考核点。

### 离线模式说明

未配置 LLM Key 时，`/api/qa` 走抽取式回答：按问题与句子的关键词重合度挑出最相关的 2-3 句教材原句，
标注"（离线检索模式）"与参考章节。该模式同样走完整检索链路，用于零依赖演示与自动化测试。

## 五、后续优化方向

1. 关系抽取引入"每对候选点显式询问"的两阶段方案，提高 PREREQUISITE 方向准确率；
2. 知识点抽取引入章节级停用词表，进一步压缩"了解""掌握"等课程目标句式造成的误抽；
3. 检索阶段接入 embedding 召回（当前为词频打分），提升问句与教材表述差异大时的召回率（赛题允许的可选增强）；
4. 建立提示词回归测试集：每次修改提示词自动跑一遍固定样例，对比抽取结果 diff。
