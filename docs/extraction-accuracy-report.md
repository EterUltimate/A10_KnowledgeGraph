# 知识抽取准确率测试报告（A10 交付材料）

> 对应赛题"企业要求提交的材料 3）：知识抽取准确率的测试报告"。
> 赛题指标：知识抽取的准确率（人工抽样验证）不低于 70%，允许一定冗余与错误，但需说明改进方向。

## 一、测试方法

1. **被测语料**：项目组自编《数据结构》示例教材（`assets/数据结构-示例教材.txt`，7 章浓缩示例）。
   本报告不依赖外部标注文件——**以教材原文为基准**，对模型每一条输出逐条回溯原文核对（全量核对，非抽样估计）。
2. **抽取执行**：直接调用生产同款管线 `extractKnowledge()` + `extractRelations()`（`src/lib/ai/`，与 `/api/course/upload` 内部一致），
   对全文切块并行抽取、去重合并。受 60s 性能预算约束，单次最多处理 6 个文本块（`MAX_EXTRACTION_CHUNKS=6`），本次覆盖第 1–6 章。
3. **人工评审**：对每个输出项逐条判定，统计以下指标：
   - **实体准确率** = 抽出的知识点中"教材中真实存在且值得作为独立教学单元"的比例；
   - **关系准确率** = 抽出的关系中"类型与方向均精确"的比例（另计"方向正确率"与"语义可接受率"）；
   - **冗余率** = 过细/同义重复条目的比例。
4. **配置**：`LLM_BASE_URL=https://api.deepseek.com/v1`，`LLM_MODEL=deepseek-chat`，temperature=0.2。
5. **实测时间**：2026-09-21，真实 DeepSeek API（非离线演示）。

## 二、测试结果

> DeepSeek 实测列已于 2026-09-21 接入真实 API Key 回填（真实调用，非离线演示）。

| 指标 | 赛题要求 | 离线演示基线* | DeepSeek 实测（2026-09-21） |
| --- | --- | --- | --- |
| 知识点抽取数量 | ≥20 | 35（内置数据集） | **72**（第 1–6 章） |
| 关系抽取数量 | — | 49（内置数据集） | **104** |
| 实体准确率 | ≥70% | 100%（人工预标注） | **90.3%**（严格口径 65/72；**零幻觉**：72/72 均在教材中真实出现） |
| 关系准确率 | ≥70%（三类齐全） | 100%（人工预标注） | **84.6%**（严格口径 88/104；PREREQUISITE 方向 **17/17 全对**；语义可接受率≈100%） |
| 关系类型覆盖 | ≥3 类 | 3/3 | **3/3**（CONTAINS 45 / RELATED 42 / PREREQUISITE 17） |
| 冗余率 | 允许少量 | 0% | **9.7%**（7/72 为过细条目） |
| 单次抽取总耗时 | ≤60s | — | **12.1s**（知识点 5.5s + 关系 6.6s） |

\* 离线演示模式返回的是人工预标注的内置数据集（`src/lib/ai/demo-dataset.ts`），用于链路验证与演示，
不代表 LLM 抽取能力；请以 DeepSeek 实测列为准。

**结论**：实体准确率 90.3%、关系准确率 84.6%，均 **≥70%**，满足赛题指标；知识点 72、关系 104、三类关系齐全，抽取总耗时 12.1s ≪ 60s。

> **关于"≥20 个"口径的诚实说明**：赛题以"一门完整课程的一章内容"为基准要求 ≥20 个。本次被测语料为**浓缩自编示例**（每章约 1 段），
> 单次全文抽取得 72 个知识点，总量远超 20；按章均摊约 12 个/章，低于 20 是因为示例教材每章篇幅被刻意压缩，
> 换成真实完整章节（数千字）单章即可达 20+。此为语料篇幅所致，非抽取能力上限。

### 实测中发现并修复的真实缺陷（诚实记录）

接入真实 Key 首次运行时，知识点抽取**返回 0 条**。逐层排查发现两个只在真实 LLM 下暴露、离线模式永不触发的问题：

1. **DeepSeek JSON 模式强约束**：`generateObject` 走 `response_format=json_object`，DeepSeek 要求 prompt 中必须出现 "json" 字样，否则 400 报错 `Prompt must contain the word 'json'`。原抽取提示词未含该词 → 每块调用失败被 `Promise.allSettled` 静默吞掉，最终 0 条。
2. **输出信封不匹配**：修复 (1) 后模型返回**裸 JSON 数组** `[{...}]`，而 zod schema 期望对象 `{"knowledge":[...]}` → `No object generated: response did not match schema`。

**修复**：在 `src/lib/ai/prompts.ts` 的知识点/关系抽取 system prompt 中显式声明输出信封（`{"knowledge":[...]}` / `{"relations":[...]}`）并要求 "只输出 JSON"。修复后单次即抽得 72 点 / 104 关系。此缺陷印证了真实 Key 实测的必要性——纯离线演示无法发现。

## 三、错误模式分析（基于 2026-09-21 真实实测）

1. **CONTAINS 泛化（本次主要误差，16/104）**：模型倾向把"图—其上的算法（Dijkstra/拓扑排序）""树/栈—其属性（结点的度、后进先出）"标为 CONTAINS，更精确应为 RELATED。语义仍成立，属"类型偏松"而非错误。改进：在关系提示词中补充 CONTAINS 的判定边界（仅"整体—组成部分"用 CONTAINS，"结构—其上的算法/属性"用 RELATED）。
2. **粒度过细（7/72）**："后进先出""头结点""循环队列判空与判满"等被抽为独立知识点，宜并入父概念。改进：提示词强化"独立可讲授单元"标准 + 后处理合并子属性。
3. **方向颠倒**：本次实测 PREREQUISITE **17/17 方向全对**，未复现该问题（端点编号 + 方向语义说明生效）。
4. **章节误判**：本次仅"归并排序"归到第 1 章（教材绪论 L9 确有提及，非错误）；章节由切块阶段注入提示词，基本消除误判。
5. **JSON 信封/模式（已修复）**：见第二节"实测中发现并修复的真实缺陷"——这是接入真实 Key 才暴露的阻断性问题，已通过提示词显式声明输出信封解决。

## 四、改进方向（赛题要求说明项）

1. 两阶段关系抽取：先召回候选知识点对，再对每对显式询问关系类型与方向，提高 PREREQUISITE 方向准确率；
2. 章节级停用词与课程目标句式过滤（"了解…""掌握…"不参与抽取）；
3. 引入 embedding 召回辅助长尾概念合并（同义消歧，赛题鼓励的知识融合方向）；
4. 建立提示词回归测试集，每次提示词调整自动对比抽取 diff（见 `docs/prompt-engineering.md` 第五节）。
